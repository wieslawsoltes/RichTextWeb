# Word feature audit and implementation plan

Audit date: 2026-09-19; resumed and updated 2026-09-20. Baseline: `7f6242b6355b7448bf975a96f12aa18a161ea9a7` (0.5.0). This audit covers the core model/engine, every top-level source module, reusable controls, adapters, formats, tests and Document Studio. It is a capability and qualification inventory, **not a claim of complete Microsoft Word parity**. A preserved DOCX element is not necessarily editable or rendered faithfully; an exposed command is not evidence of complete Word semantics.

The authoring increment adds table formulas and sorting, repeated-header authoring, captions and cross-references, a caption index, expanded fields, native document properties/variables, and reusable dialogs/keyboard commands. It also fixes field cache loss, offsets around embedded objects, caret remapping, inherited field metadata during typing and caption continuation. All document mutations go through the reusable engine and history; the sample is a client, not a second implementation.

## New authoring contract

See [WORD-AUTHORING.md](WORD-AUTHORING.md) for runnable examples and command names. The new standalone helpers are exported from the normal/core entry points. The table formula resolver is internal coordination; applications use `DocumentFeatures` or `evaluateFormula` with an explicit reference callback.

A formula is parsed, never executed as JavaScript. Supported functions are `ABS`, `AND`, `AVERAGE`, `COUNT`, `DEFINED`, `FALSE`, `IF`, `INT`, `MAX`, `MIN`, `MOD`, `NOT`, `OR`, `PRODUCT`, `ROUND`, `SIGN`, `SUM`, `TRUE`. Parsing is bounded to 8,192 characters, 2,048 tokens and 64 nested parse levels; evaluation has an 8,192-step budget and 10,000 referenced/aggregate-value caps. Table grids have a 10,000-cell cap. Field instructions, date/number pictures and dependency recursion are separately bounded.

A1 and RnCn references resolve in the nearest containing table. Ranges and directional references deduplicate merged cells and exclude the formula cell; directional references exclude marked header rows. Bare `R`/`C` refer to the current row/column; an A1-looking name takes A1 precedence. Numeric dependencies resolve before formatting. Cross-table bookmarked ranges, general external data and the full Word numeric/date/locale grammar are not implemented. Date pictures use UTC; unsupported instructions preserve cached display and return a reason instead of silently evaluating to a fabricated result.

Sorting preserves row/cell/node IDs and rich formatting, keeps the caret with the original paragraph and uses the existing history/review machinery. It sorts within existing body row groups to retain group inheritance, supports one to three keys and rejects vertical merges. Date keys require ISO dates or timezone-qualified timestamps. Repeated-header authoring partitions real header/body groups for DOM `thead` rendering and emits native `w:tblHeader`; it does not establish Word-identical repeated-header pagination.

Caption creation, its three bookmark targets and sequence update are one undo action. Caption metadata does not leak into a newly typed following paragraph. Headless reference resolution defaults to the pre-update source snapshot. `ReferenceMode: "Current"` resolves supported REF chains and bookmarked formula operands against pending results in one pass; reusable Update fields/F9 commands use this mode. It handles cycles, locked caches, original-offset remapping and bounded expansion. General nested instruction evaluation, persistent incremental scheduling, contents rebuilding and layout/TOC fixed points remain outstanding. Page/section fields need valid layout context; the page control supplies measured page information only for its current document revision.

## Content controls and forms — continuation on 2026-09-20

Baseline for this continuation: `5c47d249b0222e837b5e07bdeb2a58f8fa220614` (PRs #22–24, 510 Node tests). The new form contract lives in [CONTENT-CONTROLS.md](CONTENT-CONTROLS.md).

- **Model/engine:** `content-controls.ts`, `engine.ts` and `engine-tree.ts` provide inline/block rich text, plain text, checkbox, dropdown, combo and Gregorian-date controls. Typed values are distinct from rendered labels. Metadata includes titles, data tags, placeholders, independent deletion/content locks, local required-value/length rules and stable control identities. Normal text edits, paste, partial copying, exact annotation mapping, undo, validated review restoration and atomic multi-control filling use the existing engine, not sample-only code.
- **Native interchange:** `content-control-docx.ts` and `formats-docx.ts` read/write WordprocessingML SDTs, native locks, choice values, dates, Office 2010 checkbox states/fonts and placeholder glossary parts. Tests strip private extension data to exercise native semantics. Unsupported/malformed control properties retain their body with `ContentControlImportWarnings`. Required/maximum-length rules are RichTextWeb application metadata, not native Word constraints.
- **Controls/sample:** `content-control-ui.ts`, `control-renderer.ts`, `control.ts` and `toolbar.ts` supply accessible control boundaries, checkbox activation, typed value/property dialogs, isolated rich drafts, JSON form fill/inspection, required-value validation, stale-edit/read-only guards and rejected-input reporting. `sample/forms.js` builds eight real controls using public APIs; Developer ribbon actions share the reusable toolbar. The sample is also tested headlessly through native DOCX.
- **Qualification:** 66 added Node regressions bring the suite to **576**. Node tests include all six types at inline/block levels, native DOCX without extensions, unsupported-binding diagnostics, placeholders, locks, partial copies, review/undo, atomic fill/replace-all and existing rich collaboration transport. Nine browser groups exercise the actual dialogs, activation, sample, mobile bounds and stale/read-only behavior. Browser test presence is not a pass: consult this continuation's exact-commit CI results. Local Chromium navigation is blocked by environment policy; no Microsoft Word desktop open/save or visual comparison has been performed.

Remaining form work includes picture, repeating-section and building-block controls; custom XML/XPath/database binding; full Word style propagation; legacy form fields; whole-document restricted editing and editable-region permissions; arbitrary partial structural editing; form-focused navigation/proofing; and cross-browser/assistive-technology qualification. A lock is an editing rule, not authentication, encryption, signatures or server authorization. Trusted model loading and authoritative collaboration remain host capabilities. Concurrent edits to the same typed control require broader conflict/intent qualification; the added transport regression establishes sequential synchronization only.

## Document-theme continuation

`document-theme.ts` adds validated twelve-slot RGB palettes, one-hop semantic color mapping, Latin major/minor font roles, symbolic tokens and HSL tint/shade resolution. The model, engine, selection queries and renderer resolve references below direct formatting without rewriting canonical values. Style capture retains homogeneous theme references; theme updates, detach, undo and story-draft conflicts use the shared engine. `document-theme-ui.ts` supplies preview/customization and selection tools, and the style manager exposes theme links. The Design ribbon and the new `themes` sample use public APIs, keeping existing Home style commands visible at desktop widths.

`document-theme-docx.ts` and `formats-docx.ts` implement native theme parts, mappings, Latin font and foreground/shading references, including table-cell shading. Native tests remove private metadata. Theme/settings/relationship digests invalidate relevant stale snapshots; this is not exhaustive cross-part integrity. Missing/malformed schemes and unsupported script/effect semantics produce explicit fallback warnings. External theme links are inert.

The increment adds **47 Node regressions (679 total)** and **seven browser groups (148 when the full suite passes)**. See [DOCUMENT-THEMES.md](DOCUMENT-THEMES.md) for exact APIs, reproduction, rounding qualification and acceptance limits. Exact-commit CI—not test presence—defines browser/package/native-host pass status. Full Word script/font selection, embedded fonts, effects/drawing themes, native table/border themes, template organizers, package-wide snapshot integrity and Word visual/open-save qualification remain.

## Mail-merge continuation

Baseline: `9a283040829824a3d92746e10a75eb3c3bba07ed` (#27, 679 Node tests / 148 browser groups). `mail-merge.ts` adds bounded local scalar/CSV/TSV/semicolon validation, ten filter operators, flat All/Any queries, typed three-key stable sorting, inclusive ranges and original-row selection. `MailMergeSession` snapshots the template/records/plan and produces detached rich previews and independent generated documents, with diagnostics and optional all-or-error generation. Native MERGEREC, MERGESEQ and supported MERGEFIELD before/after text are retained in DOCX. Table formula locations/grid caches now use node object identity across independent stories rather than ambiguous reused IDs.

`mail-merge-ui.ts` supplies the shared local-source/query/recipient/preview dialog, 50-row table paging, validation, stale/read-only guards and generation events. The Mailings ribbon and `mailings` invitation template share those APIs. Generated outputs are reviewed before explicit DOCX/JSON download or document replacement; no recipient list is persisted or sent to a service. The core exposes up to 32 flat conditions; the dialog exposes three. Queries do not emulate every mixed AND/OR, locale or external database behavior.

The continuation adds **53 Node regressions (732 total)** and **eight integrated Chromium groups (156 when all pass)**. Native DOCX cases remove private metadata; the sample is exercised both headlessly and through its ribbon. Local Chromium navigation is policy-blocked; exact-commit CI determines browser/package/native-host results.
